# Release draft: ShadowGraph 0.43.0 (candidate, not released)

Status: **draft for owner approval.** The version in `package.json` stays 0.42.3. No tag, GitHub Release, npm, Glama or social post exists for this draft. It becomes the `RELEASE_NOTES.md` head only when the owner approves the release.

## Proposed summary

Claude Code CLI automatic experience memory on Windows. After a one-time setup:
- ordinary `claude` CLI sessions are captured durably, including while the store is busy;
- they are extracted automatically by a separate, owner-selected Claude model through a confined `claude -p` executor;
- fresh sessions receive that experience at start and with relevant prompts.

The accepted Codex workflow and the MCP surface are unchanged.

## Changes (from `CHANGELOG.md`, Unreleased)

- Durable capture spool with oldest-first replay, content-free loss markers, and waiting/dropped input reported by delivery.
- Runtime-evidence extraction profile for Claude Code 2.x, with per-invocation confinement checks and explicit `--model`. A `{}` remote-settings cache is not counted as managed policy; real policy sources still block.
- Quoted extraction recipe with corrections on the Claude route. A user's correction supersedes the user's earlier decision; a decision kept verbatim as a memory is linked to the correction and marked as corrected, not closed.
- `shadowgraph sharing project|selected|all-permitted`: owner-confirmed, revocable delivery grants.
- Delivery: lines before full records, with a longer line for decisions, at SessionStart and UserPromptSubmit.
- Extraction: an output refused by the executor's own checks is asked once more, within the frozen budgets.

## Evidence to cite

The Claude Code guide, under *Support and evidence*, and the private review package of 2026-10-27: Windows 11, Claude Code CLI 2.1.302 and 2.1.312 (print mode), Haiku host, Haiku/Sonnet extractor, English and Arabic inputs.

## Known limits to carry into the notes

- On Windows with Claude Code 2.1.302 or earlier, `claude -p` exits only after the extraction worker it started has finished, after printing its result (about 1 to 2 minutes, at most 4). Claude Code 2.1.312 exits at once while the worker continues (verified live). Recommend 2.1.312 or later.
- Using the experience before acting is shown when a fresh session is asked about it, and on an Arabic coding task whose earlier experience the repository does not hold (against a no-memory control). The session did not name the earlier work.
- A user's decision may be kept as verbatim memory (strict claim verification; owner rule).
- An assistant's decision is kept only when the rest of its message is plain (strict claim verification; owner rule). In the fifth live run, on the final build, a summary that also named the rejected alternative kept none of it.
- Extraction quality varies by model: Sonnet met the criterion in runs 1 to 4; Haiku once missed the decision.
- Not verified: Claude Desktop, the interactive TUI, resume flows, macOS and Linux hosts.
