## 2. F29 – F32 status

### F29 — Basic Memory storage accounting · **CLOSED** (`dcffeee`)

The adapter reported MEASURED bytes by walking the project directory, on the
stated premise that "the arm's records are the files in it". Basic Memory 0.23.2
writes note bodies to `note_content.markdown_content` in a SQLite index shared by
every project and defers the markdown write to a queue the adapter never drains.
Run 002 residue, verified independently: nine `note_content` rows per state root,
all `file_write_status='pending'`, 14,765–15,156 chars of markdown, **zero
regular files** in the project directories — while the same units carry
`persistenceEvidence.verified: true`. The arm was publishing **MEASURED 0 bytes
for namespaces that held records**.

Fix: `STORAGE = not_available_storage(...)`, as mem0 and cognee already do.
LB2c's clearance withdrawn in `CANDIDATE-STATUS.md`. Regression: 3 tests
replaced; restoring the MEASURED claim fails **6 tests across 3 classes**.

### F30 — scorer rewarded absent answers · **CLOSED** (`3496d1d`, `01bce10`)

Three defects of one shape. `falseAlertRate` divided by the probes it found and
read a null as a correct negative, against `preregistration.json:280` ("Null,
malformed, or missing is a failed unit, not a negative prediction"), so an arm
answering none of the three posted the best rate in the run.
`projectIsolation`/`userIsolation` returned **1 — best, on a hard security
gate** — for a probe that returned nothing. And the persisted-state half of that
rule was never consulted at all: it read `leakedRecordIds` and `persistedLeak`,
neither of which any adapter writes.

Fixes: rate is N/A when any probe failed, never 0, with probe counts beside it;
a 1 requires both halves; the real evidence (`verified` plus two match counts) is
read and a match count overrules an adapter's own `verified`. Two further
fail-opens found by closure review and closed in `01bce10`: `null <= 0.05` is
`true` in JavaScript, so both threshold gates now demand a finite rate **and** a
finite limit; and `isolationInspectionFrom` no longer lets `verified: true` stand
as a confirmation when the match counters are absent.

Frozen v1.0 isolation scores are unchanged. `falseAlertRate` does change for
v1.0, deliberately — `preregistration.json:280` is v1.0's own rule and the old
code violated it there too — and no published v1.0 result moves, because
`benchmark/results/` holds no v1.0 raw run.

### F31 — `decisionRetrievalAccuracy` · **OPEN — dependency identified**

The earlier description was wrong in both halves and is corrected. The model
**is** asked for `decisionId` (the field contract is sent on every phase) and the
record id **is** in native context as `record.id` — four Phase-E units in run 002
returned a real `decision:<hex>` copied from an eight-record context. What is
missing is semantics: nothing in the frozen prompt contract says what the field
should contain, so a model returning `null` complied with everything it was told.
Observed: `null`×152, `'D001'`×28 (every one at `nativeContextCount == 0`, so
invented), real ids ×4.

**Exact dependency: an owner-authorised amendment.** Not evidence, not
infrastructure, not effort. Both levers are frozen — the outer system prompt is
hashed into `outerPromptBinding.systemSha256`, and the response schema sits
verbatim in `preregistration.json` → `promptProtocol.responseSchema`. Fixing it
in the scorer would be changing a rule so the current data passes, which the
methodology forbids.

Options and a recommendation: `v11-f31-amendment-proposal-2026-09-06.md`. It is
**inert** — nothing loads it, no `amendment-004.json` exists, and
`v11-definition.mjs` takes amendments by explicit filename with a `.sha256`
sidecar each.

### F32 — the harness showed the model its own prior answer · **CLOSED for every shape run 002 produced**, residual tracked as F37

`standardizedDecisionRecord` stores each decision response verbatim as the
record's content; adapters return record content verbatim as native context; and
`canonicalJson` sorts keys, so the rendered prompt opened with
`{"content":{"changedFactDetected":null,…`. **64 of 64** nulls occurred in arms
with retrieved context; **0 of 12** in the control.

Fix: `serializeNativeContext` drops `changedFactDetected`, `changedFactId` and
the prior `decisionId` echo before rendering, **matching on the key at any
depth**. `record.id` survives. Validation and the byte cap both still run on the
unredacted record, so a boundary violation still rejects and no payload that used
to be refused is now admitted. The stored record keeps all fifteen frozen fields
and still satisfies the adapter protocol's exact-keys validator on both the JS
and Python sides. **Both prompt-binding hashes recomputed after the fix still
match run 002's recorded values.** 14 tests; 13 mutants, all killed.

The first version of this fix matched the *path* `record.content.<key>`, which
covers only the shape `logical_record` produces. Independent closure review
demonstrated that nested, sibling-key and array-wrapped records went straight
through; those are closed now, with tests. **A record serialised into a string is
still not covered** — that is Cognee's real retrieve shape, and it is **F37**.

### Also open

**F37** key-based redaction cannot reach inside a string, so a provisioned
cognee arm would still be shown the pre-filled answer fields while the other arms
are redacted. No exposure in run 002 — cognee returned zero native context, 40 of
its 44 units having failed — but cognee is one of the seven required arms, so
this blocks a run in which cognee is provisioned. Remedy identified and costed in
the findings report · **F33** reconciliation verdict never reaches the aggregate · **F34** identical
`commonExecution.repetitions` key path in `acceptance/definition.json` (2) and
`preregistration.json` (3) with nothing saying they are different protocols ·
**F35** the v1.0 `persistedLeak` fail-open, left open deliberately so a v1.1
repair does not restate frozen v1.0 results · **F36** the corrected 156/132 is
prose only; `aggregate.coverage` still reports 204/84 because it counts unit
status · **F28** Basic Memory's isolation namespace is never registered.

## 7. What was deliberately not done

- **No provider traffic, no acceptance run, no scored run.** No container
  started, stopped or altered.
- **No push, publication, release, or product-version change.**
- **No model switch.**
- **No gate weakened.** Where the code and the frozen text disagreed, the code
  moved. Where the frozen text is itself the problem (F31), it is recorded as
  needing an amendment rather than reinterpreted.
- **No re-scoring of run 002**, and no derived report presented as a new
  measurement. Every corrected number in the findings report is traceable to the
  preserved artifact, and where a corrected number has no artifact behind it —
  the 156/132 split — that is stated in the report and tracked as F36.
